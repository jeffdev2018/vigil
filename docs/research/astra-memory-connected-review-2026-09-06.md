# Connected memory comparisons — 6 September 2026

## Scope

Human memory managers can launch a text-response comparison from the existing web/desktop Evaluations dialog. The selected agent needs an explicit model and an online Claude or Codex runtime advertising `memory-evaluation-v1`; launching also requires runtime owner/admin access. The UI shows provider/model/effort and asks for distinct replay/holdout prompts and expected answers. Four runs execute sequentially, using frozen agent instructions, workspace context and active/candidate memories. The API supports 2–8 cases.

The existing report table owns the durable queue, request identity and partial/final results. One daemon evaluation runs at a time. Claiming is atomic and one-time; a crash or lost claim response never automatically replays paid work. Identical result callbacks are acknowledged, changed/out-of-order callbacks rejected. Expected answers are excluded from runtime jobs; authorized human reports retain them for review/export. The server grades exact text matches after trimming ends. Failed, cancelled, expired or incomplete runs cannot authorize adoption. Completed runs use the existing human review and atomic memory-version/context adoption check.

This mode uses local runtime accounts and permissions in fresh temporary folders. It is not an OS sandbox, fully frozen provider configuration, repository benchmark or reproduction of all production tools. Project files, custom agent environment/arguments, skills and authenticated Multica MCP are omitted; launch-prefix profiles are rejected. Codex reuses the existing disposable-home configuration/authentication helper. Each response is limited to 60 seconds, with an 18-minute worker and 20-minute server deadline; cancellation stops subsequent runs and may wait for the current response plus subprocess cleanup. Adapter-internal retries remain provider-specific and deadline-bound. Provider usage and identity are reported observations, not billing or attestation.

Server migrations 496–498 and an updated daemon are required when deploying. No deployment, installed daemon restart, provider request or production database migration was performed. Native mobile and actual LLM-quality/cost measurement remain open. Connected JSON can be exported/imported and summarized by `pilot-summary`; evaluated adoption is through the UI/API. The older offline CLI `adopt` flow requires its own server-bound report.
