ワークスペースは Multica の最上位の境界です。メンバー、タスク、プロジェクト、エージェント、スキル、実行履歴はすべていずれか 1 つのワークスペースに属し、互いに完全に分離されています。

## ワークスペースの構成

| 分類 | 内容 |
|---|---|
| **作業** | タスク、プロジェクト、コメント、添付ファイル、実行履歴 |
| **チーム** | メンバー、ロール、招待 |
| **エージェント** | エージェント設定、スキル、ランタイム、自動化 |
| **共有設定** | コンテキスト、ラベル、カスタムプロパティ、連携 |

**コンテキスト**はワークスペース内のすべてのエージェントに渡されます。チームの背景、プロダクトの約束事、長期的に有効な要件を書く場所です。一回限りの要件は、対応するタスクに書いてください。

## ワークスペースの作成

作成時に入力するのは 3 つです。

- **名前**: メンバーに表示されます。後から変更できます。
- **ワークスペース URL**: アドレスに使われる slug です。`multica.ai/my-team` の `my-team` にあたります。小文字、数字、ハイフンのみが使え、既存のワークスペースや予約済みアドレスとは重複できず、作成後は変更できません。
- **タスク接頭辞**: ワークスペース URL から自動で入力され、作成前に変更できます。接頭辞が `MUL` の場合、タスク番号は `MUL-1`、`MUL-2` と表示され、ワークスペース内で独立して増えていきます。大文字と数字のみ、最大 10 文字で、あとから設定でも変更できます。

作成者は自動的に `owner` になります。

## 設定の変更

`owner` と `admin` は名前、アイコン、説明、コンテキスト、タスク接頭辞を変更できます。`member` は閲覧のみです。

![ワークスペース設定：名前、コンテキスト、slug、タスク接頭辞と危険区域](/images/docs/workspace-settings.webp)

<Callout type="warning">
タスク接頭辞を変更すると、すべてのタスクがただちに新しい番号に切り替わります（`MUL-5` が `NEW-5` になります）。ただし、PR、ブランチ名、チャット履歴にある古い番号は更新されません。
</Callout>

## 切り替えと退出

1 つのアカウントで複数のワークスペースに参加できます。切り替えは現在表示している範囲を変えるだけで、データは一切移動しません。

ワークスペースを退出した後に戻るには、あらためて招待を受ける必要があります。退出すると同時に、自分が所有するランタイムは無効化され、それに紐づくエージェントはアーカイブされ、未完了の実行はキャンセルされます。

最後の `owner` は退出できません。先に別のメンバーを `owner` に昇格してください。

## 使用量の上限

Cloud のサブスクリプションは、**タスク数**、**オートパイロット実行回数**、**シート**の上限を課せます。Multica が強制するのは、自ら制御する境界だけです。

| 上限 | 制御境界 | 上限到達時 |
|---|---|---|
| タスク数 | タスク作成（API / トリアージ / クイック作成） | 作成を明示的に拒否 |
| オートパイロット実行 | 期間内の新しい自動化実行の受付 | 実行は開始されない。所有者/管理者は期間ごとに最大 1 件の Inbox 通知を受けられる |
| シート | 人間メンバーまたは招待の追加 | シート購入またはメンバー退出まで拒否 |

設定 → 請求に現在の使用量、上限接近時の警告（約 80%）、および Multica が新規作業を拒否する「上限到達」状態が表示されます。

<Callout type="info">
これらの上限は、すでに実行中のプロバイダー CLI を**止めません**。Multica のキュー外の GitHub・クラウド・モデル費用も止めません。実行上のプロバイダークォータエラーは、ワークスペースのプラン上限とは別です。
</Callout>

## ワークスペースの削除

ワークスペースを削除できるのは `owner` だけです。削除すると、その中の作業、メンバー、エージェント設定、実行履歴のすべてが完全に削除され、復元できません。しばらく離れるだけなら、削除ではなく退出を選んでください。
