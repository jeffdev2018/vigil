Multica における会議とは、録音された会話のことです。音声は進行中に文字起こしされ、停止すると要約され、そこに含まれるすべての約束事は Triage に保留項目としてキューイングされます。課題として取り込む（accept）か、却下する（dismiss）かはあなた次第です。

<Callout type="info">
音声は一切保存されません。各チャンクは文字起こしされたあと破棄されます。保存されるのはテキスト、要約、アクションアイテムだけです。
</Callout>

## 録音

**会議 → 会議を録音**で録音が始まります。ブラウザはまずマイクへのアクセスを求め、続いてタブやウィンドウの共有を提案します。これにより他の参加者の音声も収録できます — 断っても構いません。その場合、会議はあなたのマイクだけで録音され、レコーダーがその旨を表示します。

録音中であることを示すインジケーターはどのページでも表示され続けるため、他のページに移動しても停止できます。停止することで会議が終了します — 会話の末尾がアップロードされ、要約が書かれ、アクションアイテムがキューイングされます。

録音を保持しているのは、それを開始したタブだけです。他の人、あるいは同じ人が別のタブを開いた場合は、「この会議は他の場所で録音中です」と表示されます。

<Callout type="warn">
参加者には文字起こしされていることを伝えてください。レコーダーにも同じ注意書きが表示されますが、同意を取るのはあなたの責任であり、プロダクト側の責任ではありません。
</Callout>

### 録音が中断された場合

会議の途中でタブを閉じると、会議は `recording` のまま、それを終了させる手段がなくなります — レコーダーはそのページ上でしか動いていなかったからです。会議を開いて**会議を終了**を使ってください。これは録音者本人と、ワークスペースの管理者・オーナーであれば誰でも実行できます。その時点までに文字起こしされていた内容は、通常どおり要約されます。

要約が返ってこなかった場合（サーバーが再起動した、当時モデルが設定されていなかった、など）、会議は `summarizing` のまま残ります。5 分経つとページは待機をやめ、**要約を再生成**を提示します。これは同じ処理をやり直すものです。そこで生成されたアクションアイテムは、重複を作るのではなく、すでにキューにあるものへ統合されます。

## デスクトップアプリでの会議検出

デスクトップアプリは、Zoom、Meet、Teams、Slack ハドル、FaceTime、各種ブラウザなど、会議アプリがマイクを使い始めたことに気づき、メモを取ることを提案できます。あくまで確認を促すだけで、勝手に録音を始めることはなく、Multica 自身が録音している間は何も表示しません。

検出には、macOS では同梱の CoreAudio ヘルパーを、Linux（PulseAudio / PipeWire）と Windows ではオペレーティングシステム自身が持つ録音ストリームの一覧を使います。**設定 → 環境設定 → 会議 → 会議を自動検出**でオフにできます。オフにすると、アプリはマイクの監視を完全にやめます。

## ライブ文字起こしとバッチ文字起こし

文字起こしの経路は 2 つあり、どちらが使われるかはサーバーの設定によって決まります。

- **バッチ**は常に使われます: 音声は約 30 秒ごとのチャンクでアップロードされ、届くたびに文字起こしされます。プロバイダーが話者ラベル付けに対応しており、それが有効な場合、文字起こしには話者が付き、会議ページでは発言の切り替わりごとに段落が分かれて表示されます。
- **ライブ**はリアルタイムモデルが設定されている場合に動作します: ブラウザがサーバーによって発行された短命のトークンを使い、プロバイダーのリアルタイムソケットを直接開き、話された言葉がそのまま表示されます。ライブの文字起こしには話者ラベルは付きません。ソケットが切断された場合、録音はバッチ経路で続行されます。

会議ページでは、文字起こしはデフォルトで折りたたまれています — その上にある要約こそが、たいていの場合、あなたが見たかったものです。

## 要約とアクションアイテム

会議を停止すると、文字起こしがワークスペースの言語モデルに送られ、短い Markdown の要約（決定事項、未解決の論点、次のステップ）と、最大 15 件のアクションアイテムが返されます。アクションアイテムは、それを裏付ける文字起こしの逐語的な抜粋をモデルが示せる場合にのみ残されます。

各アクションアイテムは、課題としてではなく**保留中の Triage 項目**になります。判断するのは人です。承認すると課題が作られ、その課題には元になった会議の刻印が付き、録音へ戻る「会議から」リンクが表示されます。

モデルが設定されていない場合、または呼び出しが失敗した場合でも、会議自体は完了し、文字起こしは保持されます — ページには要約が作成されなかった旨が表示され、モデルが利用可能になったときのために**要約を再生成**が用意されています。

## 設定

会議には音声認識（speech-to-text）プロバイダーが必要です。OpenAI 互換の `POST {base}/v1/audio/transcriptions` を話すサービスであれば動作します: Mistral Voxtral、OpenAI、Groq、あるいは vLLM 上でセルフホストする Whisper / Qwen3-ASR など。

| 変数 | 内容 |
| --- | --- |
| `MULTICA_STT_BASE_URL` | プロバイダーのベース URL。空にすると会議とボイスメモが無効になります。 |
| `MULTICA_STT_API_KEY` | プロバイダーの API キー。 |
| `MULTICA_STT_MODEL` | 文字起こしモデル。これも空にすると機能が無効になります。 |
| `MULTICA_STT_LANGUAGE` | ISO 639-1 のヒント（例: `fr`）。空にするとプロバイダーが自動検出します。 |
| `MULTICA_STT_DIARIZE` | `true` にすると、対応するプロバイダー（Voxtral）に話者ラベル付けを依頼します。 |
| `MULTICA_STT_REALTIME_MODEL` | ライブの逐語文字起こしに使うモデル。空にするとライブ経路が無効になります。 |

プロバイダーが設定されていない場合、API は `409 stt_not_configured` を返し、UI はアップロード時に失敗を出すのではなく、控えめな通知の裏に機能を隠します。

セルフホスティングのその他の設定については、[環境変数](/docs/environment-variables) を参照してください。
