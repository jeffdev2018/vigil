收件箱汇总与你有关的工作动态。它不是完整的活动日志，而是提醒你"哪里发生了需要关注的变化"；完整上下文仍然保存在对应的任务中。

## 收件箱的内容

常见通知包括：

- 任务分配给你，或从你名下移走；
- 你订阅的任务出现新评论，或负责人、状态、优先级和日期发生变化；
- 有人在任务描述或评论中 @你；
- 你创建的任务或评论收到表情回应；
- 你订阅的任务中，智能体执行失败；
- 通过智能体创建任务的操作完成或失败；
- 你订阅的自动化创建了新任务，或自动化因连续失败被暂停。

自己的操作不会通知自己。同一任务的多条通知会合并成一项，打开后可查看这条任务最近的变化。

## 自动订阅的来源

以下参与者会自动订阅任务：

- 任务的创建者；
- 新的负责人；
- 发表评论的人；
- 在任务描述中被新增 @提及的人；
- 自动化中预先配置的订阅成员。

负责人变更不会取消原有订阅。可以在任务页面随时订阅或取消；取消后普通更新不再进入收件箱，直接 @你仍会单独通知。

<Callout type="info">
子任务的状态发生变化时，也会通知父任务的订阅者。子任务的评论、优先级和日期变化不会向父任务冒泡。
</Callout>

## 智能体不使用收件箱

收件箱只面向工作区成员。即使智能体是负责人或订阅者，它也不会读取收件箱通知。

在评论中 @智能体、把任务分配给智能体或触发自动化，都会直接创建一次执行，而不是给智能体留一条通知。`@all` 也只通知成员。

## 处理通知

选择一条通知会把它标为已读。处理完后可以归档；归档不会修改或删除对应的任务。任务进入 `in_review`、`done` 或 `cancelled` 分类下的任一状态后，它的"执行失败"通知会自动归档。

右键点击一条通知，可以使用**标为已读** / **标为未读**和**归档**（在"已归档"视图中是**取消归档**）。标为未读表达的是"我看过了，但还没处理完"：该通知重新变为未读，未读数也会回升；即使它还开着也会保持未读——之后再打开一次才会照常标为已读。已归档的通知会保留已读状态，因此恢复时会原样回来。

收件箱菜单还可以：

- 全部标为已读；
- 归档全部或全部已读；
- 归档状态为 `done` 或 `cancelled` 的任务通知；
- 打开"已归档"并恢复某条通知。

## 筛选需要处理的通知

在网页和桌面端，打开 **筛选收件箱 → 需要处理**，只显示标记为需要处理的通知。数量会随其他筛选条件变化。除非同时启用"只看未读"，否则阅读通知不会将其移出结果。可以组合发送者、状态和优先级条件，也可以在已归档视图中使用。

筛选依据是每个任务当前显示的最新通知，不是尚未解决的决策清单：后续通知可能替换较早的请求。打开任务查看完整讨论。筛选不会回答问题、批准操作或重启智能体。

## 调整通知类型

打开**设置 → 通知**，可以分别开关：

- 分配；
- 状态变更；
- 评论；
- 提及；
- 优先级与日期；
- 智能体活动。

关闭某一类后，相关变化仍然保存在任务中，只是不再创建收件箱通知。表情回应、快速创建结果和自动化暂停等少数类型不受这六组控制，始终投递。系统通知和浏览器通知控制的是桌面横幅，不会改变收件箱本身。

## 决策请求

在收件箱顶部打开 **决策请求**，处理发给你的问题。这份列表独立于通知的已读和归档状态。**待处理** 保留未回答的请求，以及已回答但尚未启动后续运行的请求；**历史记录** 保留已取消或已启动后续运行的请求。

选择建议选项或输入回答，再点击 **保存回答**。选择选项不会直接提交。回答保存后无法修改，也不会自动启动智能体。取消请求需要再次确认。

源运行结束后，点击 **启动后续运行**，即可把已保存的问题、背景和回答传给新的运行。你需要拥有运行该智能体的权限。运行时不可用或存在待执行工作时，回答仍会保留；重试会返回同一条运行记录。记录只表示运行已入队，不代表工作已完成。工具操作审批和交付审核仍按原有规则执行。

**决策记录** 显示源运行、请求人和回答人。删除任务或工作区时，相应记录也会删除。该功能使用 Web 和桌面端的共享界面，打开期间每15秒刷新，每页加载50条。智能体可通过 `multica issue decision request` 发起请求，参数和来源要求见内置 `multica-working-on-issues` skill。创建请求不会暂停进程；智能体应保存工作并结束当前运行，由接收人明确启动后续运行。
