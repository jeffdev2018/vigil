Multica는 모든 워크스페이스를 하나의 [MCP](https://modelcontextprotocol.io) 서버로 노출합니다. MCP 클라이언트 — Claude Code, Codex, Cursor, 스크립트, 또는 Multica 내부에서 실행되는 에이전트 — 가 여기에 연결해 워크스페이스의 도구를 찾아 호출합니다. 이슈, 댓글, 목표 루프, Brain, 프로젝트, 에이전트, 트리아지, 인박스, 실행 기록은 모두 도달할 수 있습니다. 삭제, 시크릿, 멤버 관리, 승인, 청구는 의도적으로 도달할 수 없습니다.

무엇을 할 수 있는지는 클라이언트가 아니라 서버가 결정합니다: 도구별·호출자별로 **allow**, **ask**, **deny** 중 하나입니다. 이 결정은 워크스페이스의 것이며 클라이언트가 협상할 수 없습니다.

## 클라이언트 연결하기

엔드포인트는 Multica 서버의 `POST /api/mcp/{workspace-slug}`입니다(스트리밍 가능한 HTTP, 요청당 JSON 응답 1개, 세션 없음). [개인 액세스 토큰](/members-roles)(`mul_…`)으로 인증합니다.

```json title="Claude Code · .mcp.json"
{
  "mcpServers": {
    "vigil": {
      "type": "http",
      "url": "https://multica.example.com/api/mcp/acme",
      "headers": { "Authorization": "Bearer mul_xxx" }
    }
  }
}
```

```toml title="Codex · config.toml"
[mcp_servers.vigil]
url = "https://multica.example.com/api/mcp/acme"
http_headers = { Authorization = "Bearer mul_xxx" }
```

Cursor와 다른 클라이언트도 같은 URL과 header를 사용합니다. 경로에 slug가 없으면 `X-Workspace-Slug` 또는 `X-Workspace-ID`를 보내세요. Multica 내부에서 실행되는 에이전트 실행은 자신의 실행 토큰으로 같은 엔드포인트에 도달합니다 — 워크스페이스는 그 토큰에서 결정됩니다.

## 두 가지 surface

URL에 `?surface=compound` 또는 `?surface=granular`를 추가하거나, **설정 → MCP 서버**에서 워크스페이스 기본값을 설정합니다.

- **compound**(기본값): 도메인마다 하나씩, 총 아홉 개의 도구가 각각 `action` 인자를 가집니다 — `vigil_issue`, `vigil_goal`, `vigil_brain`, `vigil_project`, `vigil_team`, `vigil_triage`, `vigil_inbox`, `vigil_run`, `vigil_handoff`. 클라이언트의 컨텍스트를 적게 씁니다.
- **granular**: 작업마다 도구 하나(`issue_create`, `note_create`, `goal_answer` 등) — 명시적인 스키마를 선호하는 클라이언트를 위한 것입니다.

두 surface 모두에서 이름이 그대로 동작하므로, 한쪽 카탈로그를 캐시한 클라이언트도 계속 동작합니다.

## 결정: allow, ask, deny

모든 도구에는 위험 등급이 있습니다(읽기 또는 내부 쓰기뿐이며, 카탈로그에 외부용이거나 민감한 것은 없습니다). 먼저 호출자의 상한이 적용됩니다 — 멤버는 읽기와 내부 쓰기를 단독으로 수행할 수 있고, 에이전트는 자신의 [신뢰 다이얼](/agents)이 정하는 상한을 얻습니다 — observer는 읽기만 할 수 있습니다. 워크스페이스 admin은 **설정 → MCP 서버**에서 어떤 도구든 **ask** 또는 **deny**로 더 조일 수 있습니다 — 재정의가 상한을 완화하는 일은 없습니다.

**ask**의 의미는 호출자에 따라 다릅니다.

- **멤버의 클라이언트**는 확인 토큰과 평이한 설명이 함께 붙은 *보류* 상태로 호출 결과를 돌려받습니다. 클라이언트는 곧 일어날 일을 사람에게 보여주고 같은 호출을 `confirm_token`과 함께 다시 보냅니다. 토큰은 정확히 그 호출에 묶여 있으며 10분 뒤 만료됩니다.
- **에이전트 실행**은 민감한 도구 호출이나 git push처럼 해당 실행에 승인 게이트가 기록됩니다 — 사람이 앱에서 판단합니다. 보류된 결과는 그 게이트의 이름을 담고 있고, 실행은 `vigil_gate_wait`로 이를 폴링하며, 승인되면 `gate_id`와 함께 같은 호출을 다시 보냅니다. 거부된 게이트는 최종입니다.

**deny**는 이유를 담은 명확한 거부입니다. 모든 호출은 결정과 결과와 함께 감사 로그에 `mcp.inbound_call`로 기록되며, 모든 호출자는 분당 120회로 제한됩니다.

## 클라이언트가 보는 것

도구 결과는 API 자체의 JSON이며, 워크스페이스 기록은 다른 사람과 에이전트가 작성한 데이터일 뿐 지시가 아니라는 안내가 함께 붙습니다. 도구 호출은 앱 및 CLI와 같은 핸들러를 거칩니다: 전환 규칙이 적용되고(상태 변경이 *승인 대기 중*으로 돌아올 수 있습니다), 이벤트는 열려 있는 클라이언트에 도달하며, 감사 로그는 토큰 뒤에 있는 행위자를 기록합니다.

## 설정

`GET /api/mcp-server/settings`는 워크스페이스의 설정과 각 도구의 위험 등급을 포함한 전체 카탈로그를 반환합니다. `PUT`(owner와 admin)은 `{ "enabled", "default_surface", "tools": { "<tool>": "allow" | "ask" | "deny" } }`를 받습니다. 서버를 끄면 명확한 메시지와 함께 모든 호출을 거부하며, 그 외에는 아무것도 바뀌지 않습니다.
