并不是所有想成为任务的东西都应该成为任务。每次部署都会触发的 Webhook、任何人都能输入 `/issue` 的支持群组、把自己发现的问题直接提交的智能体、被转发的邮件——这些都可能在没有人判断"这值得成为任务"之前，就把工作丢到你团队面前。

Triage 就是保存这些素材的队列。队列里的一个项目**不是任务**：它不占用任务编号，不出现在任何列表、汇总或去重检查中。只有接受它，才会创建任务。

## 队列

侧边栏中的 **Triage** 会按最新优先显示待处理的项目，每一条都附带它的来源和到达的内容。你可以在这里接受一个项目（它会经过普通的任务漏斗——查重、配额、事件、智能体分配——变成一个任务），也可以丢弃它。

重复会被合并：如果第一条还在待处理时，同一个来源又发来了相同的标题，不会新增第二条，而是让已有项目上的计数增加。

## 你能对一个项目做什么

接受并不是唯一的结果，队列上方的标签页（待处理、已延后、已接受、已丢弃、已合并）会让已处理的项目继续保持可读。

- **接受**会创建任务。**接受为…**可以指定负责人、落在哪个项目、优先级是什么，而不是继承来源自动化原本会赋予的值。留空则保持继承。
- **合并到任务…**会把这个项目并入一个已经在跟踪同一工作的任务。不会创建第二个任务：项目会变为 `merged`，目标任务上会出现一条系统评论，说明合并进来的是什么。
- **延后**会把项目搁置到你选择的时间（一小时后、今晚、明天、下周一，或者自定义日期——最长 30 天）。被延后的项目状态仍是 `pending`：延后只是隐藏工作，从不解决它。它会离开待处理标签页，在队列统计中单独计数，时间一到会自己回来。
- **丢弃**可以附带一个理由。它是可选的，但已丢弃标签页和自动分类器之后都会读取它，所以值得填写。
- **重新打开**会把已丢弃的项目送回待处理，无论最初是谁丢弃的——人、规则，还是分类器。

用复选框选中多个待处理项目，可以把它们一起接受或丢弃，批量丢弃共用一个理由。批量操作会为每个项目分别返回一个结果，所以摘要里点名的是*没有*通过的那些。

### 智能体的判断

智能体可以对一个待处理项目提出判断建议，但仅此而已：项目仍保持待处理，状态不变，建议会显示为"智能体建议：接受/丢弃"，并附上智能体给出的理由。做决定始终只属于人类——每个状态变更端点都会拒绝智能体作为操作者，而判断端点则相反，会拒绝人类作为操作者。

在 CLI 中：

```bash
multica triage list --pending
multica triage list --state dismissed --include-snoozed --output json
multica triage verdict <item-id> --accept --reason "matches last week's outage"
```

`multica triage verdict` 要求 `--accept` 和 `--dismiss` 二者中必须且只能指定一个。

### 键盘操作

这个队列是一份不用鼠标也能浏览的列表。`J` / `K`（或上/下方向键）在各行之间移动，`Enter` 打开当前聚焦的项目，`Esc` 关闭详情。在打开的项目上：`A` 接受，`X` 丢弃，`S` 打开延后菜单，`M` 打开合并目标选择器，`R` 重新打开一个已丢弃的项目。当你正在某个字段中输入，或有菜单处于打开状态时，这些快捷键都不会触发；它们都可以在**设置 → 键盘快捷键**中重新绑定。

## 来源

**来源**是流入素材的一个出处。每个来源都是独立的，所以你可以只把吵闹的那个设为保留，而不动其他来源。

| 来源 | 单位 | 到达时机 |
| --- | --- | --- |
| 自动化 Webhook | 自动化触发器 | 外部系统向该触发器的 Webhook URL 发送请求时 |
| 自动化时间表 | 自动化 | cron 触发器触发时 |
| 频道 | 已安装的频道 | 有人在 Slack、Telegram、飞书/Lark、钉钉或企业微信中输入 `/issue` 时 |
| 智能体创建 | 智能体 | 智能体主动提交一个任务时 |
| 快速创建 | 工作区 | 自然语言输入创建任务时 |
| 会议 | 会议 | 录制会议的摘要产生行动项时 |
| 邮件 | 工作区 | 消息被转发到工作区的接收端点时 |

同一个自动化会算作两个来源：它的 Webhook 和它的时间表可以分别设置保留，因为无人值守的 cron 和带签名的 Webhook 信任级别并不相同。

来源会在第一次投递任何内容时出现。你不能手动创建来源。

## 模式

每个来源都处于三种模式之一。除邮件外，**直接**是所有来源的默认模式。

- **直接** —— 就像 triage 不存在一样，任务会被立即创建。频道还会记录一条影子项，这样在你决定是否把它设为保留之前，就能在队列统计中看到这个来源的真实流量。
- **保留** —— 不会创建任何东西。素材会在队列里等待。处于保留状态的频道会告诉发送者，他们的报告正在等待审核；处于保留状态的智能体或快速创建，API 会返回 `202` 和队列条目，而不是任务。
- **已拦截** —— 素材会被拒绝，且这次拒绝会被记录下来，所以被拦截的来源是可审计的，而不是悄无声息地消失。

<Callout type="warn">
拦截是拒绝，不是暂停：不会有任何东西被留到以后处理。想看看到达的内容时，请使用保留模式。
</Callout>

队列头部的**来源**按钮会列出每个来源投入队列的内容——仍然待处理的条目数、过去 24 小时收到的条目数、过去 24 小时被丢弃的条目数——并排显示产生这些数字的设置。哪个来源在丢弃投递，就该去调高它的上限。

每个来源还有另外三项设置：

- **自动接受** —— 无需人工介入，把该来源的项目直接解析为任务。它走的是普通的接受路径，所以任务漏斗、事件和配额都不受影响。默认关闭。
- **每小时上限** —— 一道防止刷屏的天花板。超过上限的项目会被记录为 `rate_limited` 并丢弃，而不是继续堆满队列。`0` 表示没有上限。
- **保留期（天）** —— 未解决的项目能存活多久，见下文。

## 邮件接入

**设置 → 工作区 → 邮件接入**会为每个工作区生成一个端点：

```
POST /api/triage/inbound/email/{token}
```

路径中的 token 就是全部凭证——不需要 session，也不需要工作区请求头。它只在创建或轮换时显示一次：服务端只保存它的摘要，所以丢失的 token 只能轮换，无法找回。轮换会让旧 token 立即失效。

请求体是一个小型 JSON 对象：

```json
{
  "from": "reporter@example.com",
  "subject": "Checkout returns 500 on Safari",
  "text": "Since this morning, paying with Apple Pay fails.",
  "html": "<p>Since this morning…</p>",
  "message_id": "<abc@example.com>"
}
```

`from` 是必填项，还需要 `subject` 或 `text` 二者之一。主题（subject）会成为该项目的标题（没有主题时用正文的第一行代替），正文（text）会成为它的内容。

这是各家邮件服务商发送的 JSON 入站 Webhook 的最大公约数，因此转发规则需要的是字段映射，而不是解析器：

| Multica | Mailgun | Postmark | SendGrid |
| --- | --- | --- | --- |
| `from` | `sender` | `From` | `from` |
| `subject` | `subject` | `Subject` | `subject` |
| `text` | `body-plain` | `TextBody` | `text` |
| `html` | `body-html` | `HtmlBody` | `html` |
| `message_id` | `Message-Id` | `MessageID` | 来自 `headers` |

邮件接入创建时就是**保留**模式，并且刻意没有直接模式：转发来的消息是这个产品里认证程度最低的素材，所以它总是要等人来处理。

## 规则

工作区规则可以在项目被捕获的那一刻——在任何人看到它之前——就解决它。规则挂在 `webhook.received` 这个点上，读取项目的来源类型和名称、标题、正文与 payload、合并计数，以及当时的时间。第一个条件成立的规则会应用它的动作——**丢弃**，或者带上可选优先级和负责人的**接受**。

规则位于**设置 → 工作区 → 业务规则**，而某个项目详情里的**创建规则**会打开同一个编辑器，并预填该项目的来源和标题中的一个关键词——通常是在队列里，看着促成这条规则的那次投递时才会想到要建一条规则。接受动作可以路由给某个成员，也可以路由给某个智能体。没有规则匹配的项目会保持待处理。

## 自动分类

每一次接受和丢弃，都是队列可以学习的判断依据。开启自动分类后（**设置 → 工作区 → Triage 自动分类**，默认关闭），如果最相近的过去判断在置信度阈值之上达成一致，该项目就会在无需点击的情况下被分类。这需要预先存在最少数量的人工判断，被丢弃的项目也始终可以重新打开。

无论如何，建议都会显示；这个设置只控制它们是否被自动应用。

自动判断会被记录为系统所为，而不是某个人所为：项目会显示"由队列自动接受"以及支撑这一判断的置信度，而不是某个从未点击过的人的名字。自动接受创建的任务依然需要一个创建者，那就是该来源的创建者。

## 保留期

没有人处理的项目，会在其来源的保留期（默认 14 天）过后**过期**。过期会释放标题，让同样的报告可以再次被捕获；该行会被保留而不是删除：自动分类学习的正是这些已解决和已过期的项目。

## 队列滞留摘要

队列的统计信息已经显示了最旧的待处理项目已经等了多久——但看到它的人，恰恰是已经在关注队列、根本不需要这个提醒的人。当队列悄悄没人再看时，工作区里的其他人对此一无所知。

一旦真正最旧的待处理项目（不计入已延后的项目）等待超过 48 小时，工作区的每一位所有者和管理员每天都会收到一条指向 Triage 的收件箱通知，说明有多少条待处理、最旧的那条等了多久，并且只要队列一直滞留就会持续。通知按工作区自己的时区每个日历日发送一次——正常的周末留下的队列不会在周一早上为周五的项目呼叫任何人——一旦队列恢复正常，通知会自动停止。
