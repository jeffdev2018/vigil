エージェントは [Multica ワークスペース](/workspaces)におけるコラボレーターです。タスクを割り当てる、コメントで @メンションする、直接チャットする、といった関わり方ができます。エージェントは紐づいたランタイムを通じて AI コーディングツールを動かし、進捗と結果をワークスペースに書き戻します。

エージェント自体は常時稼働するプロセスではありません。繰り返し使えるアイデンティティと設定のまとまりであり、仕事を受け取ったときにだけ具体的な[実行](/tasks)が生まれます。

## エージェントの設定項目

| 設定 | 役割 |
|---|---|
| **名前・アバター・説明** | それが誰で、何に向いているかをチームに伝えます。説明は表示専用で、実行プロンプトには入りません。 |
| **指示** | 職責、仕事の進め方、境界、成果物の要件を定めます。毎回の実行で使われます。 |
| **会話の開始例** | エージェント別の例を3件まで提示し、新しいチャットを開いたときに表示します。選ぶと送信せずに入力欄へ入ります。 |
| **スキル** | 再利用できる手法、参考資料、補助ファイルを提供します。 |
| **ランタイム・モデル・思考レベル** | どのランタイムで、どの AI コーディングツールとモデルで実行するかを決めます。一部のツール（Codex など）ではサービスティアも選べます。 |
| **Access** | どのメンバーが実行できるかを決めます。 |
| **実行設定** | 同時実行上限、環境変数、CLI 引数、MCP、外部インテグレーションを含みます。 |

モデルの変更や指示の修正で新しいエージェントが作られることはなく、過去のタスク、コメント、実行履歴も失われません。

## エージェント・ランタイム・実行

| 概念 | 役割 |
|---|---|
| **エージェント** | 誰が、どのように仕事をするかを決める |
| **ランタイム** | どのコンピュータで、どの AI コーディングツールで実行するかを決める |
| **実行** | 1 回の実行の過程と結果を記録する |

1 つのランタイムは複数のエージェントを載せられ、1 つのエージェントは時間をかけて多くの実行をこなせます。ランタイムがオフラインでも、エージェントのアイデンティティと履歴は残ります。ただし新しい実行は、ランタイムが復帰するまで待機します。

## 作業への参加方法

- **タスクを担当する** — エージェントを担当者に設定すると、実行がキューに入り次第処理を始めます。
- **コメントを処理する** — コメントでエージェントを @メンションします。タスクの担当者は変わりません。
- **議論を続ける** — エージェントのコメントに返信すると、新しい情報が以降の実行に反映されます。
- **直接チャットする** — タスクに紐づかない会話を始めます。
- **プロジェクトやスクワッドに参加する** — エージェントは、プロジェクトリードにも、スクワッドのリーダーやメンバーにもなれます。
- **オートパイロットで実行する** — スケジュールや外部イベントで所定の作業をトリガーします。手動でも実行できます。

エージェントはタスクの作成、コメントの投稿、作業ステータスの変更ができますが、インボックスを持たず、`@all` も受け取りません。エージェントへの @メンションは実行のトリガーであり、通知ではありません。

## 権限と Access

すべてのエージェントには 1 人の owner と Access 設定があります。

| Access | 実行できる人 |
|---|---|
| **Only me** | エージェントの owner だけ。 |
| **Entire workspace** | ワークスペースのすべてのメンバー。 |
| **Specific people** | エージェントの owner と指定したメンバー。 |

新しいエージェントのデフォルトは **Only me** です。

<Callout type="info">
ワークスペースの `owner` と `admin` はすべてのエージェントを見て管理できますが、Access をバイパスして他人の「Only me」エージェントを実行することはできません。一般メンバーには、自分が所有するか実行を許可されたエージェントだけが表示されます。
</Callout>

**見える**かどうかは、owner であるか、ワークスペースの管理ロール、Access の 3 つで決まります。**変更**はエージェントの owner とワークスペースの `owner` / `admin` に開かれていますが、Access だけはエージェントの owner しか変更できません。

環境変数や MCP など、認証情報を含みうる設定にはより厳しい読み取りルールがあります。[エージェントの作成と構成](/agents-create#環境変数と認証情報)を参照してください。

## オンライン・オフラインと作業状態

エージェント一覧には、2 種類のステータスが並んで表示されます。

- **可用性**はランタイム由来です — オンライン、オフライン、不安定など。
- **作業負荷**は実行由来です — 処理中、キュー待ち、アイドルなど。

「オフライン」は、エージェントが削除されたという意味ではありません。すでにキューに入った実行はランタイムの復帰を待ちます。新しい仕事を受け取れなくなるのは「アーカイブ済み」だけです。

## アーカイブと復元

使わなくなったエージェントはアーカイブできます。アーカイブすると、ピッカーに表示されなくなり、割り当ても @メンションもできなくなります。履歴は保持され、後から復元できます。

<Callout type="warning">
アーカイブすると、そのエージェントの未完了実行は、キュー待ちと実行中を含めてすべてキャンセルされます。
</Callout>

エージェントの owner と、ワークスペースの `owner`・`admin` がエージェントをアーカイブ・復元できます。

## メモリと修正

**メモリ**タブにはエージェントの短いルールを保存できます。新しい実行には、作成日時が新しく、有効かつ期限内のメモリを最大 50 件含めます。開始済みの実行には変更を反映しません。

編集画面で任意の有効期限をローカル時刻で設定できます。期限切れのメモリは表示されますが、新しい実行には含まれません。本文の編集や承認では期限を延長しません。再利用するには日付を明示的に変更または削除してください。期限を変更しても確認待ちの提案は承認されません。期限切れの項目も 200 件の上限に含まれます。

手動追加したメモリはすぐに有効になり、1 件 500 文字まで保存できます。完了した実行から抽出した提案には人の承認が必要です。プライベートチャットは抽出の対象外です。アクティビティでは、完了・失敗・キャンセルした実行に修正ルールを紐づけ、メモリタブで元の実行を確認して編集、承認、却下できます。編集だけでは承認されません。

**履歴**からバージョンを確認し、復元内容をプレビューできます。復元すると、選択した本文、確認状態、有効期限を持つ新しいバージョンを作成し、復元した人を記録します。有効かつ期限内のバージョンは新しい実行で使用され、確認待ちのものには引き続き承認が必要です。同時編集があれば履歴に戻り、最新状態を確認してから再試行してください。履歴は更新時に保存した状態から始まり、それ以前の編集は復元できません。メモリを削除すると履歴も完全に削除します。

変更できるのはエージェント所有者とワークスペースの所有者・管理者です。マシン認証情報では承認できません。確認した人と時刻を記録し、同時編集があれば再読み込みを求めます。無効化は記録を残し、再確認は確認待ちに戻します。削除は元に戻せません。

確認待ち・却下済みを含め、保存上限は 200 件です。上限で抽出を停止し、既存のメモリは自動削除しません。更新時は既存の自動抽出メモリを確認待ちに戻し、手動メモリは有効のままにします。承認は使用を許可する操作であり、効果改善の証明ではありません。

Web とデスクトップでは、メモリの **評価** からオフライン評価レポートを取り込み、候補あり・なしの結果と独立した検証ケースを確認できます。人が内容を確認した後、評価対象のリビジョンを採用できます。候補や有効なメモリが評価後に変わった場合、採用は拒否されます。レポートは人が提供した結果であり、Multica が実行を認証したものではありません。実際のモデルの改善、費用、人の作業時間は測定していません。レポートの書き出しと削除も可能です。ネイティブモバイル版の評価画面は未対応です。



実行の詳細でメモリ情報を開くと、最後に配信準備が完了した時点で選ばれたエージェントメモリの ID とバージョン、プロジェクトメモリのバージョンを確認できます。読み込み失敗と対象メモリなしは区別され、古い実行では未記録と表示されます。開始前に再取得するとスナップショットは置き換わります。全配信の履歴や、受信・遵守の証明ではありません。実行履歴にはバージョン参照のみを残し、削除したメモリ本文は残しません。

**実行間のメモリ統計**では、過去30日間に開始され、記録が残り、チャット以外と確認できる実行を集計します。削除済みのチャットと発生元が不明な古い実行は除外します。メモリあり、対象メモリなし、読み込み失敗、コンテキスト未記録を区別します。バージョン一覧を開くと、各バージョンが準備された回数と最後の実行開始時刻を確認できます。現在の本文は別途明示され、履歴から保存済みのバージョンを開けます。毎分更新されます。遵守や改善の測定ではありません。取得に失敗した場合はゼロではなくエラーを表示します。
