**章程**是工作区的长期规则：智能体在这里可以做什么、不可以做什么，工作怎么交付，哪些事没有人参与就绝不会发生。一份由工作区 owner 撰写的文档，注入每一个智能体的 brief。它就是工作区上下文长大后的样子 —— 带版本、可审核、可引用。

## 它出现在哪里

每一次运行的 brief 都会在任务和评论之前，以 `## Workspace Doctrine (revision N)` 标题完整载入章程。聊天运行、任务运行、自动化运行、快速创建运行 —— 同一份正文，同一个版本号。

brief 里其它每个区块都是数据 —— 任务正文、评论、Brain 笔记、CRM 记录，都是智能体*读到的东西*。章程正相反：它就是指令，brief 里也这么写明。章程**高于所有记录**：一条评论无法授权章程禁止的事，一条与章程矛盾的笔记是过期，不是例外。唯一与章程并列的是智能体自己的[指令](/agents#智能体的配置项)。

章程不能推翻的是平台自身的拒绝 —— 工作区禁止的[状态流转](/issues)、超过阈值的支出、审批门。这些依然生效。

## 怎么写

**设置 → 章程**里有编辑器、版本号和历史。发布的权限属于工作区的 `owner` 和 `admin`，阅读对每位成员开放。上限是 **32 000 字节** —— brief 每次都完整携带章程，所以一份长到几页以上的章程，是在每一次运行上付账。

发布需要带上你读到的那个版本号（`expected_revision`）。如果在你写的时候别人已经发布过，这次写入会被拒绝，而不是合并：重新读一遍，再发布。

<Callout title="两个入口，一个台账">
`multica workspace update --context` 依然可用，也不是后门：它走同一个台账、留同一条审计记录，发布一个章程版本。
</Callout>

## 第二位审核人

**设置 → 章程 → 需要第二位审核人**打开后，发布变成提案。正文不会生效，而是记为**待审**，其他 owner 和 admin 会收到一条 `doctrine_review` 收件箱项，由其中一人批准或驳回。批准后它成为生效版本；驳回则章程原地不动，审核人的备注留在记录里。

只有一位 owner 或 admin 的工作区自行批准 —— 否则打开这个开关就等于把章程冻住。待审提案同时只能有一个：先批准或驳回，再发布下一个。

## 历史、差异和恢复

每个版本都留着：正文、写的人、备注、审核的人，以及它是 `active`、`pending`、`rejected` 还是 `superseded`。历史按时间倒序分页。

**差异**按行比较任意两个版本 —— 新增、删除、未变。不指定对比对象时，待审或被驳回的提案与生效的章程对比，已生效的版本与它前一个版本对比。

**恢复**把某个历史版本的正文作为一个*新*版本重新发布（台账会记下它来自哪个版本）。它和任何一次发布走同样的审核策略，不存在原地改写。

## 上报 —— 当规则无法遵守

撞墙的智能体不会自己编一个解释，也不会闷头把活干完。它会提交一条**章程上报**：

| 类型 | 含义 |
| --- | --- |
| `refusal` | 不违反某条规则就无法完成任务。 |
| `conflict` | 两条规则同时适用，无法同时遵守。 |
| `ambiguity` | 规则确实存在，但说得不够，无法据此行动。 |

一条上报带着摘要、可选的原文引用、它来自哪一次运行和哪个任务，以及**智能体当时依据的版本号** —— 章程之后被改过，上报依然能对着当时的正文读懂。成员也可以提交。

每条上报都会作为 `doctrine_report` 收件箱项和推送，发给所有 owner 和 admin。owner 随后**确认**它（问题真实存在，正在处理）或**驳回**它（章程写得没错），两种情况都可以留备注。上报本身不改变任何东西：它是"这份治理文档需要人来看一眼"的信号，不是在这一次运行里豁免某条规则的手段。

## 工具与 CLI

- 原生运行时：`report_doctrine_conflict` —— 它在运行的有效动作预算之外，所以预算已经花完的运行仍然能说出自己被某条规则挡住了。
- MCP：`vigil_doctrine`，动作 `get`、`versions`、`report`。发布、批准和恢复被有意排除在外 —— 一次运行不能改写约束自己的规则。
- CLI：`multica doctrine show | publish | history | diff | approve | reject | restore | report | reports | acknowledge | dismiss`。

```bash
multica doctrine show
multica doctrine publish --file DOCTRINE.md --expected-revision 7 --note "adds the release rule"
multica doctrine diff <version-id>
multica doctrine reports --status open
```

## API

- `GET /api/workspace/doctrine` → 正文、版本号、`byte_limit`、`require_review`、`can_publish`、待审版本、未处理上报数。
- `PUT /api/workspace/doctrine {content, expected_revision, note?}` → `200` 已发布，`202` 待审核，`409` 版本已过期或已有待审提案。
- `GET /api/workspace/doctrine/versions?cursor&limit`、`GET .../versions/{id}`、`GET .../versions/{id}/diff?against={id}`。
- `POST .../versions/{id}/approve | reject | restore`。
- `GET .../reports?status=open|acknowledged|dismissed|all`、`POST .../reports {kind, summary, passage?, issue_id?}`、`POST .../reports/{id}/acknowledge | dismiss`。
- 审计动作 `doctrine.published`、`proposed`、`approved`、`rejected`、`reported`、`report_resolved`；收件箱类型 `doctrine_review` 和 `doctrine_report`；`doctrine:changed` 事件让打开的页面保持最新。
