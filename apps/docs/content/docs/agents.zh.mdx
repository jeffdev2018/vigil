智能体是 [Multica 工作区](/workspaces)中的协作者。你可以把任务分配给它、在评论中 @它，或直接和它对话。它会通过绑定的运行时调用 AI 编程工具，并把进度和结果写回工作区。

智能体本身不是一个持续运行的进程。它是一套可以反复使用的身份和配置，只有收到工作时才会产生具体的[运行](/tasks)。

## 智能体的配置项

| 配置 | 作用 |
|---|---|
| **名称、头像和描述** | 让团队知道它是谁、适合做什么。描述只用于展示，不会进入执行提示。 |
| **指令** | 规定它的职责、工作方式、边界和交付要求。每次执行都会使用。 |
| **对话开场建议** | 提供最多三条针对该智能体的示例，出现在别人与该智能体开始新对话时。选择后只会填入输入框，不会发送。 |
| **Skills** | 提供可以复用的方法、参考资料和支持文件。 |
| **运行时、模型和思考强度** | 决定在哪个运行时、用哪款 AI 编程工具和哪个模型执行；部分工具（如 Codex）还可选择速度档。 |
| **Access** | 决定哪些成员可以运行它。 |
| **执行配置** | 包括并发上限、环境变量、CLI 参数、MCP 和外部集成。 |

更换模型或修改指令不会创建新智能体，过去的任务、评论和执行记录也不会丢失。

## 智能体、运行时和运行

| 概念 | 职责 |
|---|---|
| **智能体** | 决定谁来做、按什么方式做 |
| **运行时** | 决定在哪台电脑、用哪款 AI 编程工具执行 |
| **运行** | 记录这一次执行的过程和结果 |

一个运行时可以承载多个智能体；一个智能体也可以先后完成多次运行。运行时离线时，智能体的身份和历史仍在，但新的运行需要等待运行时恢复。

## 参与工作的方式

- **负责任务**：把智能体设为负责人，运行入队后开始处理。
- **处理一条评论**：在评论中 @智能体，不改变任务的负责人。
- **继续讨论**：回复智能体的评论，新的信息会进入后续执行。
- **直接对话**：开始一段不依附于任务的对话。
- **参与项目和小队**：智能体可以成为项目 lead，也可以担任小队 leader 或小队成员。
- **通过自动化运行**：按时间表或外部事件触发预设工作，也可以手动运行。

智能体可以创建任务、发表评论和修改工作状态，但它没有收件箱，也不会收到 `@all`。对智能体的 @提及是一次执行触发，不是通知。

## 权限与 Access

每个智能体都有一名 owner 和一个 Access 设置：

| Access | 谁可以运行 |
|---|---|
| **仅自己**（Only me） | 只有智能体 owner。 |
| **整个工作区**（Entire workspace） | 工作区中的所有成员。 |
| **指定成员**（Specific people） | 智能体 owner 和指定的成员。 |

新建智能体默认使用 **仅自己**。

<Callout type="info">
工作区 `owner` 和 `admin` 可以查看并管理所有智能体，但不能绕过 Access 运行别人的"仅自己"智能体。普通成员只会看到自己拥有或有权运行的智能体。
</Callout>

**看见**由 owner 身份、工作区管理角色和 Access 共同决定；**修改**开放给智能体 owner 和工作区 owner/admin，其中 Access 只有智能体 owner 能改。

环境变量和 MCP 等可能包含凭据的配置有更严格的读取规则，见[创建和配置智能体](/agents-create#环境变量与凭据)。

## 在线、离线和工作状态

智能体列表会同时展示两类状态：

- **可用性**来自运行时，例如在线、离线或不稳定。
- **工作负载**来自运行，例如处理中、排队中或空闲。

"离线"不表示智能体被删除。已经入队的运行会等待运行时恢复；"已归档"才表示它不能再接收新工作。

## 归档和恢复

不再使用的智能体可以归档。归档后，它不再出现在选择器中，也不能被分配或 @提及；历史记录保留，之后可以恢复。

<Callout type="warning">
归档会取消该智能体所有尚未结束的运行，包括排队中和进行中的运行。
</Callout>

智能体 owner 和工作区 `owner`、`admin` 都可以归档或恢复智能体。

## 记忆与纠正

**记忆**标签页保存智能体的简短规则。每次新运行会使用最近创建的最多 50 条已启用且未过期的记忆；已开始的运行不受修改影响。

可在记忆编辑器中按本地时间设置可选的到期时间。过期记忆仍可查看，但不会用于新运行。修改文本或批准记忆不会延长有效期；需要明确更改或清除日期。修改到期时间不会批准待审核的建议。过期条目仍计入 200 条上限。

手动添加的记忆立即启用，每条最多 500 个字符。运行结束后自动提取的建议需要人工审核；私人聊天不会被提取。在活动记录中，可对已完成、失败或取消的运行添加纠正，并在记忆页查看来源、编辑、批准或拒绝。编辑建议不会自动批准。

点击 **查看历史** 可查看版本并预览恢复。恢复会创建新版本，保留所选版本的文本、审核状态和到期时间，并记录恢复操作者。已启用且未过期的版本可用于新运行，待审核版本仍需批准。发生并发修改时，需返回历史查看最新状态后重试。历史从升级时保存的状态开始，无法重建更早的修改。删除记忆也会永久删除其历史。

只有智能体所有者及工作区所有者、管理员可以修改记忆，机器凭据不能批准。审核记录操作者和时间；内容发生并发修改时必须刷新后再审核。停用保留记录，再次审核会将其放回待审核列表，删除则永久移除。

每个智能体最多保存 200 条记忆，含待审核及被拒绝的建议。达到上限后停止提取，不自动清除已有记忆。升级后，旧的运行提取记忆转为待审核，手动记忆继续启用。批准只控制后续使用，不代表已验证效果提升。

在 **评估** 中，人类管理者可以导入离线比较的 JSON 报告（每份最大 2 MiB，每条记忆最多 10 份），检查有无候选记忆的结果和预留用例、导出或删除报告，并在审查证据后采纳符合条件的版本。CLI 也提供 `multica agent memory evaluate`、`publish` 和 `adopt`。采纳时会在同一事务中检查完整的活动记忆上下文并记录新版本；上下文变化后需重新评估。报告是人工提交的证据，不是服务器认证的运行，也不证明生产效果提升。成本和人工投入仍未知。删除报告不会撤销采纳；删除所引用的记忆会清理包含其文本的报告，包括基线副本。可通过记忆历史恢复旧版本。此流程支持网页和桌面端。



在运行的 **运行详情** 中展开记忆信息，可查看最近一次完成分发准备时选定的智能体记忆 ID、版本及项目记忆版本。加载失败与没有符合条件的记忆会分别显示；旧运行显示未记录。执行前重新领取运行会替换此快照。它不是每次分发的历史，也不能证明智能体收到或遵循了记忆。运行记录仅保留版本引用，不保留已删除的记忆正文。

**跨运行记忆统计**展示最近 30 天内已开始、记录仍保留且能够确定不是聊天来源的运行。聊天被删除后仍不计入统计，来源不明的旧运行也不计入。统计分别显示包含记忆、没有符合条件的记忆、加载失败和上下文未记录。展开版本列表可查看每个版本被准备的次数及最近一次运行的开始时间。当前正文单独标注；通过历史记录可查看仍保留的版本。统计每分钟刷新，不代表模型遵循了记忆或效果有所改善；请求失败时显示错误，不显示为零。
