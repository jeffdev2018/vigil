인박스는 나와 관련된 작업 활동을 모아 보여 줍니다. 전체 활동 로그가 아니라 "확인해야 할 변화가 어디에서 일어났는지" 알려 주는 곳입니다. 전체 컨텍스트는 여전히 해당 태스크에 저장됩니다.

## 인박스에 들어오는 내용

일반적인 알림은 다음과 같습니다.

- 태스크가 나에게 할당되거나 내 할당에서 해제됨
- 구독한 태스크에 새 댓글이 달리거나 담당자, 상태, 우선순위, 날짜가 변경됨
- 누군가 태스크 설명이나 댓글에서 나를 @멘션함
- 내가 만든 태스크나 댓글에 이모지 반응이 추가됨
- 구독한 태스크에서 에이전트 실행이 실패함
- 에이전트를 통한 태스크 생성 작업이 완료되거나 실패함
- 구독한 자동화가 새 태스크를 만들거나 연속 실패로 일시 중지됨

자신이 수행한 작업은 자신에게 알리지 않습니다. 같은 태스크의 여러 알림은 하나로 합쳐지며, 열면 해당 태스크의 최근 변경 사항을 확인할 수 있습니다.

## 자동 구독되는 경우

다음 참여자는 태스크를 자동으로 구독합니다.

- 태스크 생성자
- 새 담당자
- 댓글을 작성한 사람
- 태스크 설명에 새로 @멘션된 사람
- 자동화에 미리 설정된 구독 멤버

담당자가 바뀌어도 기존 구독은 취소되지 않습니다. 태스크 페이지에서 언제든 구독하거나 구독을 취소할 수 있습니다. 취소하면 일반 업데이트는 더 이상 인박스에 들어오지 않지만 나를 직접 @멘션한 알림은 별도로 전달됩니다.

<Callout type="info">
하위 태스크의 상태가 변경되면 상위 태스크 구독자에게도 알림이 갑니다. 하위 태스크의 댓글, 우선순위, 날짜 변경은 상위 태스크로 전달되지 않습니다.
</Callout>

## 에이전트는 인박스를 사용하지 않습니다

인박스는 워크스페이스 멤버만 사용합니다. 에이전트가 담당자나 구독자여도 인박스 알림을 읽지 않습니다.

댓글에서 에이전트를 @멘션하거나 태스크를 에이전트에게 할당하거나 자동화를 트리거하면 에이전트에게 알림을 남기는 대신 실행이 직접 생성됩니다. `@all`도 멤버에게만 알립니다.

## 알림 처리

알림을 선택하면 읽음으로 표시됩니다. 처리한 뒤 보관할 수 있으며, 보관해도 해당 태스크가 변경되거나 삭제되지 않습니다. 태스크가 `in_review`, `done`, `cancelled` 카테고리에 속한 상태가 되면 그 태스크의 "실행 실패" 알림은 자동으로 보관됩니다.

알림을 오른쪽 클릭하면 **읽음으로 표시** / **읽지 않음으로 표시**와 **보관**("보관됨" 뷰에서는 **보관 해제**)을 쓸 수 있습니다. 읽지 않음으로 표시는 "보긴 했지만 아직 끝내지 않았다"는 뜻입니다. 알림이 다시 읽지 않음이 되고 읽지 않은 개수도 다시 올라가며, 열어둔 상태에서도 읽지 않음으로 유지됩니다. 나중에 다시 열면 평소대로 읽음으로 바뀝니다. 보관된 알림은 읽음 상태를 유지하므로 복원하면 그대로 돌아옵니다.

인박스 메뉴에서는 다음 작업도 할 수 있습니다.

- 모두 읽음으로 표시
- 전체 또는 읽은 알림 모두 보관
- 상태가 `done` 또는 `cancelled`인 태스크 알림 보관
- "보관됨"을 열고 특정 알림 복원

## 조치가 필요한 알림 필터링

웹과 데스크톱에서 필터 메뉴의 **조치 필요**를 선택하면 조치가 필요한 것으로 분류된 알림만 표시됩니다. 개수에는 다른 필터 조건도 반영됩니다. 읽지 않은 알림만 표시하는 필터를 함께 켜지 않는 한, 읽어도 결과에서 사라지지 않습니다. 보낸 사람, 상태, 우선순위와 조합하거나 보관함에서도 사용할 수 있습니다.

각 태스크에 현재 표시되는 최신 알림을 기준으로 필터링합니다. 미해결 결정 목록은 아니며, 나중 알림이 이전 요청을 대체할 수 있습니다. 전체 논의는 태스크를 열어 확인하세요. 필터는 질문에 답하거나 작업을 승인하거나 에이전트를 다시 시작하지 않습니다.

## 알림 유형 조정

**설정 → 알림**을 열면 다음 유형을 각각 켜거나 끌 수 있습니다.

- 할당
- 상태 변경
- 댓글
- 멘션
- 우선순위와 날짜
- 에이전트 활동

특정 유형을 꺼도 관련 변경 사항은 태스크에 계속 저장되며 인박스 알림만 생성되지 않습니다. 이모지 반응, 빠른 생성 결과, 자동화 일시 중지 같은 일부 유형은 이 여섯 그룹의 설정과 관계없이 항상 전달됩니다. 시스템 알림과 브라우저 알림 설정은 데스크톱 배너를 제어할 뿐 인박스 자체를 바꾸지 않습니다.

## 결정 요청

받은편지함의 **결정 요청** 에서 나에게 온 질문에 답할 수 있습니다. 알림의 읽음·보관 상태와 독립적입니다. **처리 필요** 에는 열린 요청과 후속 실행을 기다리는 답변, **기록** 에는 취소되거나 후속 실행이 기록된 요청이 표시됩니다.

추천 답변을 선택하거나 직접 입력한 뒤 **답변 저장** 을 누르세요. 선택만으로 제출되지 않습니다. 저장한 답변은 변경할 수 없으며 저장만으로 실행이 시작되지 않습니다. 요청 취소에는 확인이 필요합니다.

원본 실행이 끝나면 **후속 실행 시작** 으로 질문·맥락·답변을 전달하는 새 실행을 시작합니다. 해당 에이전트를 실행할 권한이 필요합니다. 런타임 오류나 대기 중인 작업이 있어도 답변은 남으며, 재시도는 같은 실행 기록을 반환합니다. 기록은 실행 접수를 뜻하며 작업 완료를 보장하지 않습니다. 도구 승인과 납품 검토는 계속 필요합니다.

**결정 기록** 에서 원본 실행·요청자·응답자를 확인할 수 있습니다. 태스크나 워크스페이스를 삭제하면 기록도 삭제됩니다. 웹·데스크톱 공통 화면에서 열려 있는 동안 15초마다 갱신하며 페이지당 50건을 불러옵니다. 에이전트는 `multica issue decision request` 로 요청할 수 있습니다. 요청 생성은 프로세스를 일시 정지하지 않습니다. 작업을 저장하고 실행을 끝낸 뒤 사람이 후속 실행을 명시적으로 시작합니다.
