Multica에서 회의는 녹음된 대화입니다. 오디오는 진행되는 동안 스크립트로 변환되고, 중지하면 요약되며, 그 안에 담긴 모든 약속은 Triage에 대기 항목으로 쌓입니다. 태스크로 수락하거나 기각할 수 있습니다.

<Callout type="info">
오디오는 저장되지 않습니다. 각 청크는 스크립트로 변환된 뒤 폐기됩니다. 남는 것은 텍스트, 요약, 액션 항목뿐입니다.
</Callout>

## 녹음

**회의 → 회의 녹음**으로 녹음을 시작합니다. 브라우저가 먼저 마이크 권한을 요청한 뒤, 다른 참가자도 함께 담기도록 탭이나 창 공유를 제안합니다 — 거절해도 괜찮습니다. 이 경우 회의는 내 마이크 소리만으로 녹음되며, 레코더가 그 사실을 표시합니다.

녹음 중임을 알리는 표시는 모든 페이지에서 계속 보이므로, 다른 곳으로 이동해도 녹음을 멈출 수 있습니다. 중지하면 회의가 종료됩니다: 남은 대화가 업로드되고, 요약이 작성되고, 액션 항목이 대기열에 쌓입니다.

녹음을 시작한 탭만 그것을 붙들고 있습니다. 다른 사람이거나 같은 사람이 다른 탭을 열면 "이 회의는 다른 곳에서 녹음 중입니다"라고 표시됩니다.

<Callout type="warn">
참가자에게 대화가 스크립트로 기록되고 있다는 사실을 알리세요. 레코더에도 같은 안내가 표시되지만, 동의를 구하는 것은 제품이 아니라 당신의 책임입니다.
</Callout>

### 녹음이 중단된 경우

회의 도중 탭을 닫으면 회의는 `recording` 상태로 남고 이를 종료할 방법이 없어집니다 — 레코더는 그 페이지 안에서만 동작했기 때문입니다. 회의를 열어 **회의 종료**를 사용하세요. 이는 녹음자 본인과 워크스페이스의 관리자 또는 소유자라면 누구나 할 수 있습니다. 그 시점까지 스크립트로 변환된 내용은 정상적으로 요약됩니다.

요약이 끝내 돌아오지 않으면(서버가 재시작되었거나, 당시 모델이 설정되어 있지 않았던 경우) 회의는 `summarizing` 상태로 남습니다. 5분이 지나면 페이지는 기다림을 멈추고 **요약 다시 생성**을 제시합니다. 이는 같은 작업을 다시 실행합니다. 이때 생성된 액션 항목은 중복을 만드는 대신 이미 대기열에 있는 항목과 합쳐집니다.

## 데스크톱 앱에서 회의 감지

데스크톱 앱은 Zoom, Meet, Teams, Slack 허들, FaceTime, 각종 브라우저 등 화상회의 앱이 마이크를 사용하기 시작한 것을 감지하고 메모 작성을 제안할 수 있습니다. 어디까지나 제안만 할 뿐, 스스로 녹음을 시작하지는 않으며, Multica 자체가 녹음 중일 때는 아무 것도 표시하지 않습니다.

감지에는 macOS에서는 번들로 포함된 CoreAudio 헬퍼를, Linux(PulseAudio / PipeWire)와 Windows에서는 운영체제 자체의 녹음 스트림 목록을 사용합니다. **설정 → 환경설정 → 회의 → 회의 자동 감지**에서 끌 수 있으며, 끄면 앱은 마이크 감시를 완전히 멈춥니다.

## 실시간 스크립트와 배치 스크립트

스크립트 변환 경로는 두 가지이며, 어느 쪽이 사용되는지는 서버 설정에 따라 달라집니다.

- **배치**는 항상 사용됩니다: 오디오는 약 30초 단위 청크로 업로드되고, 도착할 때마다 스크립트로 변환됩니다. 제공자가 화자 구분을 지원하고 활성화되어 있으면 스크립트에 화자가 표시되어, 회의 페이지는 발언자가 바뀔 때마다 문단을 나눠 보여줍니다.
- **실시간**은 실시간 모델이 설정되어 있을 때 동작합니다: 브라우저가 서버에서 발급한 단기 토큰으로 제공자의 실시간 소켓을 직접 열고, 말한 내용이 그대로 표시됩니다. 실시간 스크립트에는 화자 표시가 없습니다. 소켓이 끊기면 녹음은 배치 경로로 계속됩니다.

회의 페이지에서 스크립트는 기본적으로 접혀 있습니다 — 그 위에 있는 요약이야말로 대부분의 경우 당신이 찾던 것입니다.

## 요약과 액션 항목

회의를 중지하면 스크립트가 워크스페이스의 언어 모델로 전송되어, 짧은 마크다운 요약(결정 사항, 남은 질문, 다음 단계)과 최대 15개의 액션 항목을 반환합니다. 액션 항목은 모델이 그것을 뒷받침하는 스크립트의 원문 발췌를 제시할 수 있을 때만 남습니다.

각 액션 항목은 태스크가 아니라 **대기 중인 triage 항목**이 됩니다: 판단은 사람이 합니다. 수락하면 그 회의를 출처로 표시한 태스크가 만들어지고, 해당 태스크에는 녹음으로 돌아가는 "회의에서" 링크가 표시됩니다.

모델이 설정되어 있지 않거나 호출이 실패해도 회의는 그대로 완료되고 스크립트는 보관됩니다 — 페이지에는 요약이 작성되지 않았다는 안내가 표시되고, 모델을 사용할 수 있게 되었을 때를 위해 **요약 다시 생성**이 준비되어 있습니다.

## 설정

회의에는 음성-텍스트(speech-to-text) 제공자가 필요합니다. OpenAI 호환 `POST {base}/v1/audio/transcriptions` 규격을 따르는 서비스라면 무엇이든 동작합니다: Mistral Voxtral, OpenAI, Groq, 또는 vLLM 뒤에 올린 자체 호스팅 Whisper / Qwen3-ASR.

| 변수 | 내용 |
| --- | --- |
| `MULTICA_STT_BASE_URL` | 제공자 기본 URL. 비워두면 회의와 음성 메모가 비활성화됩니다. |
| `MULTICA_STT_API_KEY` | 제공자 API 키. |
| `MULTICA_STT_MODEL` | 스크립트 변환 모델. 이것도 비워두면 기능이 비활성화됩니다. |
| `MULTICA_STT_LANGUAGE` | ISO 639-1 힌트(`fr`). 비워두면 제공자가 자동 감지합니다. |
| `MULTICA_STT_DIARIZE` | `true`로 설정하면 이를 지원하는 제공자(Voxtral)에 화자 표시를 요청합니다. |
| `MULTICA_STT_REALTIME_MODEL` | 실시간 단어 단위 스크립트에 쓰이는 모델. 비워두면 실시간 경로가 비활성화됩니다. |

제공자가 설정되어 있지 않으면 API는 `409 stt_not_configured`를 반환하고, UI는 업로드 시 실패를 내는 대신 조용한 안내 뒤로 기능을 숨깁니다.

셀프 호스팅의 나머지 설정은 [환경 변수](/docs/environment-variables)를 참고하세요.
