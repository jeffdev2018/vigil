人にしか判断できない場面があります。2 つのアプローチのどちらを取るか、破壊的な操作を本当に実行してよいか、曖昧なタスクで実際に意図されていたことは何か。エージェントは推測したり止まったりする代わりに、選択肢付きの型付き質問である **Decision Card** を発行し、回答を得てから続行できます。

## Decision Card

カードは質問、2〜8 個の選択肢（それぞれ id・ラベル・任意の 1 行の影響説明を持つ）、任意の推奨選択肢、緊急度（`low`、`normal`、`high`）で構成されます。メンバーがタスクから手動で発行することもできます。

保留中のカードはタスクの**判断**セクションに表示され、選択肢ごとにボタンが並びます（推奨の選択肢が先頭）。どの選択肢も合わない場合のための自由記述（「別の回答をする…」）もあります。カードには、その種の質問について読み手自身の過去の回答傾向があればそれも表示されます（例：「この種の依頼では 4 回中 3 回「リトライ」を選んでいます」）。これはヒントであり既定値ではなく、どちらもワンクリックの距離にあります。

回答は一度だけ記録されます。同じカードへの 2 回目の回答は拒否されます。タスクがエージェントに割り当てられている場合、回答は質問と選択した答えをハンドオフノートの先頭に載せた新しい実行を 1 件開始します。人が担当するタスクでは、再開する実行がないため記録された回答がそのまま残るだけです。

<Callout type="info">
ワークスペースが Decision SLA（管理者設定）を有効にしている場合、カードには期限が付きます。期限を過ぎるとカードはエスカレーションされます — まず指定された代理担当者へ、続いてワークスペースのオーナーと管理者へ — カード自体にも「期限超過」と誰に通知したかが表示されます。エスカレーションは通知を追加するだけで、カードに自動で回答することはありません。
</Callout>

## 要件インタビュー

曖昧なタスクにコードを書き始める前に、エージェントは 1 件ずつではなく最大 3 件の選択式の質問を同時に尋ねることができます。これらはグループを共有する Decision Card であり、待機中はタスクが**PM回答待ち**ステータス（このワークスペースで初めて使われたときに自動作成され、`blocked` カテゴリに属する）に置かれます。実行はグループ内のすべての質問に回答があったときにだけ再開します — すべての質問とその回答を順番にハンドオフノートの先頭に載せた新しい実行が 1 件だけ始まります。グループの一部の質問に回答しても、他が保留のままであれば他には何も起きません。

タスクごとに開けるインタビューは同時に 1 件だけです。保留中に再度尋ねようとすると拒否されます。

## どこで回答するか

- **タスク自体** — **判断**セクションにそのタスク上の全カードが並び、保留中のものが先に表示されます。
- **インボックス → 判断待ち** — 閲覧できるすべてのタスクにまたがる保留中カードを最大 5 件、[要対応リスト](/inbox#要対応)と同じ順序（リスク、次に SLA の期限）で並べ、5 件を超えた分は合計数として表示し、タスクを開かずにその場で回答できます。
- **モバイル** — **インボックス → 判断**の同じ一覧で、スワイプで回答します。右スワイプで「`<推奨の選択肢>`と回答」が現れ、左スワイプで「選択肢」が現れて全リストを開き、自由記述はプロンプトから入力します。タップまたは確定するまで何も送信されません — スワイプはアクションを見せるだけです。

カードに回答できるのは人だけです。エージェントが回答しようとすると拒否されます — 発行できるのが誰かの逆の制約です。

## CLI

カードの発行はエージェント（または API を直接叩く誰か）が行い、回答は人の操作であり UI からのみ行います。

```bash
multica decision ask <issue-id> \
  --question "失敗したデプロイをリトライするか、ロールバックするか？" \
  --option "retry=リトライ|今日の修正を生かせる可能性がある" \
  --option "rollback=ロールバック|安全だが今日の修正は失われる" \
  --recommend retry \
  --urgency high
```

`--option` は繰り返し指定でき、`id=Label` または `id=Label|impact` の形式です。最低 2 個必要です。

```bash
multica interview ask <issue-id> --file questions.json
```

`questions.json` は `{"questions": [...]}` の形式で、1〜3 件のエントリを持ち、それぞれ `{"question": "...", "options": [{"id": "a", "label": "..."}, ...], "recommended_option_id": "a"}` の形式で選択肢は 2〜8 個です。`--file -`（または `--file` を省略）は標準入力から読み込みます。

## API

| メソッド | ルート | アクター | ボディ |
| --- | --- | --- | --- |
| `GET` | `/api/issues/{id}/decisions` | メンバー | — |
| `POST` | `/api/issues/{id}/decisions` | エージェントまたはメンバー | `{question, options[], recommended_option_id?, urgency?}` |
| `POST` | `/api/issues/{id}/decisions/{decisionId}/respond` | **人のみ** | `{option_id}` または `{modified_text}` — どちらか一方 |
| `POST` | `/api/issues/{id}/interview` | エージェントまたはメンバー | `{questions: [...]}` |
| `GET` | `/api/inbox/decisions` | メンバー | 現在のユーザーの保留中カード（最大 5 件） |

## 制限

- カードには 2〜8 個の選択肢が必要で、id はそれぞれ一意、質問は最大 4 KB、各ラベルまたは影響説明は最大 512 バイトです。
- インタビューは 1〜3 件の質問を持ち、それぞれ 2〜8 個の選択肢を持ちます。タスクごとに開けるインタビューは同時に 1 件だけです（`409 interview_pending`）。
- 回答済みのカードへの再回答は `409 already_decided` を返します。
- `urgency` は `low`、`normal`、`high` のいずれかです（既定は `normal`）。
