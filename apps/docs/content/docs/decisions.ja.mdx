人にしか判断できない場面があります。2 つのアプローチのどちらを取るか、破壊的な操作を本当に実行してよいか、曖昧な課題で実際に意図されていたことは何か。エージェントは推測したり止まったりする代わりに、選択肢付きの型付き質問である **Decision Card** を発行し、回答を得てから続行できます。

## Decision Card

カードは質問、2〜8 個の選択肢（それぞれ id・ラベル・任意の 1 行の影響説明を持つ）、任意の推奨選択肢、緊急度（`low`、`normal`、`high`）で構成されます。メンバーが課題から手動で発行することもできます。

保留中のカードは課題の**判断**セクションに表示され、選択肢ごとにボタンが並びます（推奨の選択肢が先頭）。どの選択肢も合わない場合のための自由記述（「別の回答をする…」）もあります。カードには、その種の質問について読み手自身の過去の回答傾向があればそれも表示されます（例：「この種の依頼では 4 回中 3 回「リトライ」を選んでいます」）。これはヒントであり既定値ではなく、どちらもワンクリックの距離にあります。

回答は一度だけ記録されます。同じカードへの 2 回目の回答は拒否されます。課題がエージェントに割り当てられている場合、回答は質問と選択した答えをハンドオフノートの先頭に載せた新しい実行を 1 件開始します。人が担当する課題では、再開する実行がないため記録された回答がそのまま残るだけです。

<Callout type="info">
ワークスペースが Decision SLA（管理者設定）を有効にしている場合、カードには期限が付きます。期限を過ぎるとカードはエスカレーションされます — まず指定された代理担当者へ、続いてワークスペースのオーナーと管理者へ — カード自体にも「期限超過」と誰に通知したかが表示されます。エスカレーションは通知を追加するだけで、カードに自動で回答することはありません。
</Callout>

## 要件インタビュー

曖昧な課題にコードを書き始める前に、エージェントは 1 件ずつではなく最大 3 件の選択式の質問を同時に尋ねることができます。これらはグループを共有する Decision Card であり、待機中は課題が**PM回答待ち**ステータス（このワークスペースで初めて使われたときに自動作成され、`blocked` カテゴリに属する）に置かれます。実行はグループ内のすべての質問に回答があったときにだけ再開します — すべての質問とその回答を順番にハンドオフノートの先頭に載せた新しい実行が 1 件だけ始まります。グループの一部の質問に回答しても、他が保留のままであれば他には何も起きません。

課題ごとに開けるインタビューは同時に 1 件だけです。保留中に再度尋ねようとすると拒否されます。

## どこで回答するか

人が決着をつけなければならないあらゆる依頼 — Decision Card、実行が待っている承認ゲート（git push、機微なツール呼び出し、支出）、遷移ルールでブロックされたステータス変更、ゴールループからの質問 — はすべて 1 つの**承認**であり、どこで出会っても判断できます。

- **課題のタイムライン** — 保留中の依頼は、依頼された瞬間にボタンとともにタイムライン上に現れ、タイムラインの上のバーが待機件数を示し、それぞれへジャンプできます。回答済みの依頼は履歴として**判断**セクションに残ります。
- **インボックス** — `decision_request`、`transition_approval_requested`、`goal_question` いずれかの項目の行には同じカードが表示され、課題を開かずに一覧または詳細ペインから判断できます。**インボックス → 判断待ち**は、閲覧できるすべての課題にまたがる最も緊急な依頼を最大 5 件、[要対応リスト](/inbox#要対応)と同じ順序で保持します。
- **チャット** — エージェントとチャットしている間、そのエージェントが発行した依頼が入力欄の上に表示されます。
- **モバイル** — 課題のタイムラインとインボックスの詳細に同じカードが表示され、さらに**インボックス → 判断**のスワイプ一覧もあります。
- **チャットチャンネル** — ワークスペースのダイジェストチャンネルが設定されていれば、Slack、Lark、Telegram、WeCom には承認／拒否ボタン付きで依頼が届きます（DingTalk では課題を開くボタンになります）。クリックでカードに回答すると、メッセージが結果で更新されます。クリックが拒否された場合は理由（未連携のアカウント、すでに判断済みなど）が返信で示されます。

判断できるのは人だけです。エージェントが回答しようとすると拒否されます — 発行できるのが誰かの逆の制約です。

### カード内の承認ゲート

ゲートの背後にあるカードは、判断する前にその実行が何を行うかを示します。ゲートの種類、ツールの引数（機密情報はマスク）、影響するパス、エージェントの信頼ダイヤルが許す影響範囲、そして二重承認の場合は必要な承認のうち何件が集まっているか。ゲートの期限までのカウントダウンも表示されます。ワークスペースのタイムアウト（**設定 → 承認ゲート**）内に誰も回答しなかったゲートは拒否され、そのカードはサーバーによって回答済みとなるため、放置されることなくすべてのインボックスとタイムラインから消えます。

**設定 → 承認ゲート → ゲートを判断できる人**は、ゲートをオーナーと管理者に限定する（`owner_admin`）か、課題を見られる任意のメンバーに委ねる（`any_member`、既定）かを選べます。判断できないメンバーにも依頼自体は表示され、理由が添えられます。「誰がこれを判断できるか」は「なぜこの実行が待っているか」の一部だからです。保留中のステータス変更は、そのルール自身の承認者ロールに従います。

### 全エージェントを停止

**設定 → 承認ゲート → 全エージェントを停止**は、新規実行の受け入れを止め、進行中の実行のゲート付きアクションをすべて理由付きで拒否します。停止は課題一覧とすべての課題にバナーとして表示され、誰がいつ設定したか、理由も示されます。オーナーと管理者はバナーから解除できます。拒否されたすべての依頼は、停止が原因であると示します。

## CLI

カードの発行はエージェント（または API を直接叩く誰か）が行い、回答は人の操作であり UI からのみ行います。

```bash
multica decision ask <issue-id> \
  --question "失敗したデプロイをリトライするか、ロールバックするか？" \
  --option "retry=リトライ|今日の修正を生かせる可能性がある" \
  --option "rollback=ロールバック|安全だが今日の修正は失われる" \
  --recommend retry \
  --urgency high
```

`--option` は繰り返し指定でき、`id=Label` または `id=Label|impact` の形式です。最低 2 個必要です。

```bash
multica interview ask <issue-id> --file questions.json
```

`questions.json` は `{"questions": [...]}` の形式で、1〜3 件のエントリを持ち、それぞれ `{"question": "...", "options": [{"id": "a", "label": "..."}, ...], "recommended_option_id": "a"}` の形式で選択肢は 2〜8 個です。`--file -`（または `--file` を省略）は標準入力から読み込みます。

## API

| メソッド | ルート | アクター | ボディ |
| --- | --- | --- | --- |
| `GET` | `/api/issues/{id}/decisions` | メンバー | — |
| `POST` | `/api/issues/{id}/decisions` | エージェントまたはメンバー | `{question, options[], recommended_option_id?, urgency?}` |
| `POST` | `/api/issues/{id}/decisions/{decisionId}/respond` | **人のみ** | `{option_id}` または `{modified_text}` — どちらか一方 |
| `POST` | `/api/issues/{id}/interview` | エージェントまたはメンバー | `{questions: [...]}` |
| `GET` | `/api/inbox/decisions` | メンバー | 現在のユーザーの保留中カード（最大 5 件） |

## 制限

- カードには 2〜8 個の選択肢が必要で、id はそれぞれ一意、質問は最大 4 KB、各ラベルまたは影響説明は最大 512 バイトです。
- インタビューは 1〜3 件の質問を持ち、それぞれ 2〜8 個の選択肢を持ちます。課題ごとに開けるインタビューは同時に 1 件だけです（`409 interview_pending`）。
- 回答済みのカードへの再回答は `409 already_decided` を返します。
- `urgency` は `low`、`normal`、`high` のいずれかです（既定は `normal`）。
