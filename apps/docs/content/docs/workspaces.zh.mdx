工作区是 Multica 的最上层边界。成员、任务、项目、智能体、skill 和执行记录都属于某一个工作区，彼此完全隔离。

## 工作区的组成

| 类别 | 内容 |
|---|---|
| **工作** | 任务、项目、评论、附件、执行记录 |
| **团队** | 成员、角色、邀请 |
| **智能体** | 智能体配置、skill、运行时、自动化 |
| **共享设置** | 上下文、标签、自定义属性、集成 |

**上下文**会提供给工作区中的每个智能体，适合写团队背景、产品约定和长期有效的要求。一次性的运行要求写在对应的任务里。

## 创建工作区

创建时填三项：

- **名称**：展示给成员，之后可以修改。
- **工作区 URL**：地址中的 slug，例如 `multica.ai/my-team` 里的 `my-team`。只能用小写字母、数字和连字符，不能与已有工作区或保留地址重复，创建后不可修改。
- **任务前缀**：根据工作区 URL 自动填好，创建前可以改。前缀为 `MUL` 时，任务编号显示为 `MUL-1`、`MUL-2`，在工作区内独立递增。只能用大写字母和数字，最多 10 位，之后也可以在设置里修改。

创建者自动成为 `owner`。新工作区也可以直接从一个 [pack](/packs) 开始 —— 该职能的工作项类型、视图、规则和作为同事的智能体会作为第一步装好。

## 修改设置

`owner` 和 `admin` 可以修改名称、图标、描述、上下文和任务前缀；`member` 只能查看。

![工作区设置：名称、上下文、slug、任务前缀与危险区](/images/docs/workspace-settings.webp)

<Callout type="warning">
修改任务前缀后，所有任务立即换用新编号（`MUL-5` 变为 `NEW-5`），但 PR、分支名和聊天记录里的旧编号不会更新。
</Callout>

## 用 pack 装好一个职能

[pack](/packs) 是一个文件，装好一整个职能：帮助台、运维、客户支持、销售、市场、经营、研究、人事、财务、法务。里面有这个职能需要的工作项类型、状态、标签、自定义属性、视图、规则、一段章程、一个项目，以及作为同事、处于暂停状态的智能体。安装不会覆盖工作区里已有的东西；它创建的每一行都记在这个 pack 名下，所以之后可以原地升级，也可以卸载。目录在**设置 → Pack**。

## 切换和离开

一个账号可以加入多个工作区。切换只改变当前查看的范围，不移动任何数据。

离开工作区后，需要重新接受邀请才能回来。离开会同时停用你拥有的运行时、归档绑定在其上的智能体，并取消它们未结束的运行。

最后一名 `owner` 不能离开，需要先把另一位成员提升为 `owner`。

## 删除工作区

只有 `owner` 可以删除工作区。删除会永久移除其中的全部工作、成员、智能体配置和执行记录，无法恢复。暂时不参与时选择离开，而不是删除。
